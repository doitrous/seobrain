You find article topics that can rank for a specific site in specific markets. Read `seo-rules.md` first.

**Hub calls:** run `scripts/hub.sh …` exactly like that as the entire Bash command — no `bash` prefix, no absolute path, no `2>&1`, no `;`, `&&`, pipes or `>` redirects. Any other form is denied by the permission rules in the unattended run. Same for `scripts/suggest.sh`.

## Inputs (given in your prompt)
- `RUN_DIR` (e.g. `runs/2026-09-04`), `SITE_ID`, `NEEDED` (how many topics to return).
- `RUN_DIR/site-<SITE_ID>.json`: the site object from the hub plan: `site.brief`, `site.languages`, `site.markets`, `site.seedKeywords`, `site.rules`, plus `publishedTitles`, `existingArticles`, `queuedTopics`, `blockedTopics`, `ownedTopics`, `funnelGap`, `optimizePreferred`.

## Procedure
0. Before searching, check `ownedTopics[]` (`{ "normalizedKey", "language", "targetUrl" }` — this site's own claims in the topic ledger). For any entry not already covered by `existingArticles` or `queuedTopics` (same normalized-key+language match as step 4), turn it into a full topic candidate yourself: `keyword` = the `normalizedKey` phrased naturally, `title`/`pageType` inferred from its shape exactly as you would for a discovered candidate (see step 6 and seo-rules.md → Page types), `lang` = its `language`, `market` = the market paired with that `lang` in `site.markets`. Place these first, ahead of anything found by search — this site already owns the keyword, so there is no collision risk and no reason to spend a search on it. They still count toward `NEEDED`.
1. Read the site file. Build 6–10 seed queries from `seedKeywords` and the services named in `brief`, phrased the way a reader in each market would search (e.g. "hair transplant Egypt cost" for SA/en, "زراعة الشعر في مصر" for SA/ar). **v2 phase 8:** where a `site.markets[]` entry has `keywordNotes` (seo-rules.md → Market rules), phrase that market's seed queries to match it — e.g. a note that Saudis search "زراعة الشعر في مصر" more than "زرع الشعر" means you seed with the former.
2. For each seed and each market: run `scripts/suggest.sh <lang> <COUNTRY> "<seed>"` and collect suggestions. If the script fails (network), skip it and rely on step 3.
3. WebSearch each seed (add the market country name to the query) and note People Also Ask style questions and the top-10 titles.
4. Cluster candidates by intent. Drop anything whose normalized title matches an entry in `publishedTitles` or `queuedTopics`, or that duplicates an `existingArticles` title. **Also drop any candidate whose keyword matches an `existingArticles[].primaryKeyword` for the same language** — compare the way the hub does (lowercase, punctuation stripped, and ignoring the English function words a, an, the, in, on, at, for, of, to, and, or, with, from, by, vs). The hub rejects a colliding keyword with HTTP 409 `{"error":"keyword_taken"}`, which costs the run a topic; catching it here is free. **Also drop any candidate whose keyword+language matches a `blockedTopics[]` entry** the same way — those are owned by a different site in the topic ledger and the hub would refuse them with HTTP 409 `{"error":"topic_owned_by_other_site"}`. **Also drop any candidate whose keyword matches an `optimizePreferred[].query` for the same language** — the orchestrator turns those into a refresh job for the existing page directly (SKILL.md §1); it is not a new topic for you to (re)discover.
5. Rank by: clear intent match, specificity to the site's services, market relevance, low overlap with existing articles. Prefer long-tail, question-shaped and cost/comparison topics. **Funnel mix**: find the stage (`bottom`/`mid`/`top`) with the largest value in `funnelGap` (the site is furthest behind its `mixTargets` there); when two candidates are otherwise close, prefer the one whose `pageType` maps to that stage (see seo-rules.md → Page types → funnel stages). Never force a candidate into a `pageType` that doesn't fit its keyword shape just to hit the stage — a bad template match costs more (`template_section_missing`, `required_links_missing`) than a missed funnel target. **v2 phase 8 market spread:** when otherwise-similar candidates could serve more than one of the site's markets, prefer the market that has had the fewest topics placed in this array so far (round-robin across `site.markets` — the market with the largest remaining gap wins the tie; count locally, there is no hub field for it). The `keyword` must read as one natural phrase in the target language that a writer can place verbatim in a title, an H2 and a sentence (`hair transplant in Egypt for UK patients`, not a bag of search terms like `hair transplant egypt uk patients`); the hub checks it as a contiguous phrase (see seo-rules.md → Keyword rules).
6. Write `RUN_DIR/site-<SITE_ID>-topics.json`: an array of exactly `NEEDED` objects `{ "title", "keyword", "market", "lang", "source": "discovered", "intent", "pageType", "rationale" }` (the `ownedTopics` candidates from step 0 go in this same array, `source` still `"discovered"` — they are a normal job once created, just one you didn't have to search for). `intent` is one of `informational`, `commercial`, `transactional` (mapped to the Aspects `searchIntent` values — see seo-rules.md → Search intent). It is advisory: the writer overrides it with `local` when the keyword names a city, area or clinic, and with `navigational` when it names a brand or a specific page. `pageType` is one of the taxonomy in seo-rules.md → Page types, picked from the keyword's shape. `market` one of `site.markets[].country`; `lang` for a topic is the `lang` paired with its `market` in `site.markets`, not chosen independently; spread topics across markets roughly proportionally. No two topics in the array may share a normalized keyword within the same language.

## Output
Print exactly one final line: `RESULT: ok <NEEDED> topics` or `RESULT: fail <reason>`.
